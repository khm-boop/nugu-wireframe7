🔴 클레임 처리 흐름

  • 주문 상단 버튼에서 진입: 교환/취소/반품은 주문 상단에서 시작. SG 카드에는 클레임 버튼 없음.
  • SG 선택 → 품목 선택: STEP 1에서 SG 고르면 STEP 2에 그 SG 소속 상품만 노출(예: SG-001 선택 시 SG-001 품목만).
  • 총 환불금액 확인 필요: 최종 금액만 표시. 안분/계산 상세는 미노출.

#항목주체내용
O1SG 상태 표현 방식개발SG 상태 컬럼 존재 여부 확인 필요. 별도 컬럼이 없다면 품목 상태 집계인지 / Shipping 기준 계산인지 확인 필요.
O2Order 조회 API 응답개발OrderShippingGroup 응답 스펙 확인 필요 — 배송사 / 송장정보 / SG 금액정보 포함 여부.
O3일반배송 다중 송장물류 개발대표 송장만 표시할지 / 전체 송장 펼침 제공할지 확인 필요.
O4SG 금액 노출 범위개발 기획상품금액 / 할인금액 / 배송비 / 결제금액 중 운영 화면에 어디까지 노출할지 확인 필요. 현재는 참고용 상품금액만.
O5SG 배송비 노출 정책개발 CXSG별 배송비 계산 결과를 주문상세에 노출할지 / 배송비 0엔(무료배송) SG도 노출할지 / CX가 SG 단위 배송비를 확인해야 하는지. 예) SG-001 배송비 550엔, SG-002 무료배송.
O6SG 송장 구조개발 물류SG : 송장 = 1:1 인가 / 1:N 인가. 일반배송 다중 송장 지원 여부 확인.
O7SG 상태 계산 방식개발현재 화면에 배송중/배송완료 상태 존재. SG 상태 컬럼 존재 여부 / 상품 상태 집계 여부 / 배송 상태 기반 계산 여부 확인 필요.
O8OrderShippingGroup API 응답개발주문조회 API에서 SG 단위로 내려오는 데이터 확인 필요. 예상 항목: sg_id / fulfillment_type / shipping_company / invoice_number / shipping_fee / product_amount / coupon_discount / payment_amount / shipping_status.

#요청상세
1OrderShippingGroup 응답 JSON 예시 요청주문조회 API에서 SG 단위로 실제 내려오는 JSON 구조 예시 공유. (sg_id / fulfillment_type / shipping_company / invoice_number / shipping_fee / product_amount / coupon_discount / payment_amount / shipping_status 포함 여부)
2SG 상태 계산 기준 확인SG 배송상태(배송중/배송완료)를 별도 컬럼으로 갖는지, 품목 상태 집계인지, 배송 상태 기반 계산인지.
3SG 배송비 계산 결과 제공 여부 확인SG별 배송비(550엔/무료배송)를 API가 계산해 내려주는지, FE 계산인지. 운영 화면 노출 여부 포함.
4일반배송 다중 송장 지원 여부 확인SG : 송장 = 1:1 인지 1:N 인지. 1:N이면 응답 구조와 대표 송장 지정 방식.
5SG별 금액 정보 제공 범위 확인product_amount / coupon_discount / payment_amount 중 SG 단위로 제공되는 범위. 주문 합계와의 검증 방식.
